# Combo Order System — описание проекта

## Идея

Пользователь оформляет заказ еды в приложении доставки. После успешного создания заказа система анализирует контекст заказа и предлагает пользователю вызвать такси.

Если пользователь принимает предложение, система создаёт заказ такси и связывает его с заказом еды через сущность ComboOrder.

## Бизнес-контекст

Обычно заказ еды и заказ такси существуют как отдельные сценарии. Combo Order System описывает связанный сценарий, при котором после оформления заказа еды пользователь получает релевантное предложение вызвать такси.

Цель сценария — повысить удобство пользователя и показать cross-service логику между доставкой еды и такси.

## Основной сценарий

1. Пользователь оформляет заказ еды.
2. Сервис доставки создаёт DeliveryOrder.
3. Сервис доставки передаёт данные заказа в Combo-систему.
4. Combo-система проверяет данные для создания предложения.
5. Combo-система запрашивает доступность такси.
6. Сервис такси возвращает доступность и предварительную стоимость.
7. Если условия подходят, Combo-система создаёт ComboOffer.
8. Пользователь принимает или отклоняет предложение.
9. Если пользователь отклоняет предложение, заказ еды продолжается без изменений.
10. Если пользователь принимает предложение, Combo-система проверяет актуальность ComboOffer.
11. Сервис такси создаёт TaxiOrder.
12. Combo-система создаёт ComboOrder и связывает DeliveryOrder с TaxiOrder.
13. Пользователь получает подтверждение.

## Входит в проект

- создание заказа еды;
- создание combo-предложения;
- проверка доступности такси на уровне бизнес-логики;
- принятие или отклонение предложения пользователем;
- создание TaxiOrder;
- связь DeliveryOrder и TaxiOrder через ComboOrder;
- базовая логика статусов;
- ERD и SQL-структура.

## Не входит в проект

- полноценный мобильный интерфейс;
- реальное ценообразование такси;
- трекинг водителя на карте;
- ресторанная админка;
- production backend;
- REST API, Swagger, Postman;
- полная платежная инфраструктура.

## Участники и системы

Пользователь — оформляет заказ еды, получает предложение такси, принимает или отклоняет предложение.

Сервис доставки еды — создаёт DeliveryOrder и хранит данные о заказе еды.

Combo-система — проверяет возможность создания предложения, управляет ComboOffer и ComboOrder, обновляет статусы сценария.

Сервис такси — проверяет доступность такси и создаёт TaxiOrder.

## Допущения

A-001. Пользователь уже авторизован.

A-002. Заказ еды успешно создан до момента формирования ComboOffer.

A-003. Адрес доставки доступен системе после создания DeliveryOrder.

A-004. Combo-система может проверить доступность такси на уровне бизнес-логики.

A-005. Отказ от ComboOffer не влияет на DeliveryOrder.

A-006. Ошибка создания TaxiOrder не отменяет DeliveryOrder автоматически.

A-007. ComboOrder создаётся только при принятии пользователем ComboOffer.
