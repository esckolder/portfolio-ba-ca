# User Stories

## US-001. Получение combo-предложения

Как пользователь, я хочу получить предложение вызвать такси после оформления заказа еды, чтобы совместить поездку и получение заказа.

### Критерии приемки

- предложение отображается только после успешного создания DeliveryOrder;
- предложение содержит предварительную стоимость;
- предложение содержит предполагаемое время подачи;
- пользователь может принять или отклонить предложение;
- отказ не влияет на заказ еды.

## US-002. Принятие combo-предложения

Как пользователь, я хочу принять предложение такси, чтобы система создала заказ такси, связанный с моим заказом еды.

### Критерии приемки

- после подтверждения создаётся TaxiOrder;
- создаётся ComboOrder;
- DeliveryOrder и TaxiOrder связываются между собой;
- пользователь получает подтверждение;
- при ошибке пользователь получает понятное сообщение.

## US-003. Отклонение combo-предложения

Как пользователь, я хочу отклонить предложение такси, чтобы продолжить только с заказом еды.

### Критерии приемки

- TaxiOrder не создаётся;
- DeliveryOrder остаётся активным;
- ComboOffer получает статус declined;
- пользователь возвращается к обычному сценарию заказа еды.

## US-004. Недоступность такси

Как пользователь, я не должен получать предложение такси, если такси недоступно, чтобы не видеть нерабочее предложение.

### Критерии приемки

- ComboOffer не создаётся;
- DeliveryOrder не изменяется;
- причина невозможности создать предложение фиксируется системой;
- пользователь не видит некорректное предложение.

## US-005. Истечение срока действия предложения

Как пользователь, я хочу понимать, что предложение такси ограничено по времени, чтобы принимать решение на основе актуальной стоимости и доступности.

### Критерии приемки

- ComboOffer содержит expires_at;
- после истечения срока действия предложение нельзя принять;
- при попытке принять истёкшее предложение TaxiOrder не создаётся;
- DeliveryOrder остаётся без изменений.

## US-006. Просмотр связанного combo-сценария

Как пользователь, я хочу видеть связь между заказом еды и заказом такси, чтобы понимать текущий статус общего сценария.

### Критерии приемки

- пользователь видит статус заказа еды;
- пользователь видит статус заказа такси;
- пользователь видит статус combo-сценария;
- при ошибке создания TaxiOrder пользователь получает сообщение об ошибке.
