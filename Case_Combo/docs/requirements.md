# Требования Combo Order System

## Бизнес-требования

BR-001. Система должна предлагать пользователю вызов такси после успешного оформления заказа еды.

BR-002. Предложение такси должно учитывать адрес доставки еды и предполагаемое время готовности заказа.

BR-003. Пользователь должен иметь возможность принять или отклонить combo-предложение.

BR-004. Отклонение combo-предложения не должно отменять заказ еды.

BR-005. При принятии предложения система должна создать заказ такси.

BR-006. Система должна связать заказ еды и заказ такси через сущность ComboOrder.

BR-007. Ошибка создания заказа такси не должна автоматически отменять заказ еды.

BR-008. Combo-предложение должно иметь ограниченное время действия.

BR-009. Если такси недоступно, система не должна создавать ComboOffer.

BR-010. Пользователь должен получать понятное сообщение при невозможности продолжить combo-сценарий.

## Функциональные требования

FR-001. После успешного создания DeliveryOrder система должна инициировать проверку возможности combo-предложения.

FR-002. Система должна проверить наличие необходимых данных: пользователь, заказ еды, адрес доставки, статус заказа.

FR-003. Если данных недостаточно, ComboOffer не должен создаваться.

FR-004. Система должна запросить доступность такси.

FR-005. Если такси доступно, система должна создать ComboOffer.

FR-006. ComboOffer должен содержать идентификатор предложения, предварительную стоимость, рекомендуемое время подачи и время истечения предложения.

FR-007. Пользователь должен иметь возможность принять ComboOffer.

FR-008. Пользователь должен иметь возможность отклонить ComboOffer.

FR-009. При отклонении ComboOffer TaxiOrder не создаётся.

FR-010. При принятии ComboOffer система должна проверить срок действия предложения.

FR-011. Если срок действия ComboOffer истёк, TaxiOrder не должен создаваться.

FR-012. При принятии актуального ComboOffer система должна передать команду на создание TaxiOrder.

FR-013. После успешного создания TaxiOrder система должна создать ComboOrder.

FR-014. ComboOrder должен хранить связь между DeliveryOrder и TaxiOrder.

FR-015. Если TaxiOrder создать не удалось, DeliveryOrder должен остаться без изменений.

FR-016. Система должна обновлять статус combo-сценария после значимых событий.

## Нефункциональные требования

NFR-001. Ошибка внешнего сервиса не должна приводить к потере данных основного заказа еды.

NFR-002. Все идентификаторы заказов должны быть уникальными.

NFR-003. Статусы заказов должны храниться в явном виде и быть пригодными для проверки через SQL-запросы.

NFR-004. Система должна фиксировать ошибки обработки combo-сценария.

NFR-005. Данные о связи DeliveryOrder и TaxiOrder должны быть доступны для проверки и отчётности.
